# 카드 만드는 법

Memonowz에 넣을 카드를 직접 쓰거나 LLM에게 시킬 때 보는 문서. 예시 덱은
`docs/examples/sample-deck.json`이고, **설정 → 백업 파일 가져오기**로 그대로 불러와 볼 수 있다.

## 1. 유형 두 가지

| 화면에 보이는 이름 | 저장 값 | 출제 방식 | 언제 쓰나 |
|---|---|---|---|
| 단어 | `term` | 객관식 4지선다. 오답 보기를 안 적으면 **같은 덱의 다른 단어 카드 뒷면**을 자동으로 끌어와 쓴다 | 영단어, 용어 정의 |
| 객관식 | `mcq` | 객관식. 적어준 보기만 나오고 순서는 매번 섞인다 | 기출문제, 헷갈리는 개념 비교 |

고르는 기준은 하나다. **보기를 누가 만드나** — 앱이 알아서 만들면 `term`, 네가 적어줘야 하면 `mcq`다.
단어장은 `term`, 기출문제처럼 문제와 보기가 이미 정해진 것은 `mcq`.

위 표는 **시험보기** 기준이다. **공부하기**로 들어가면 유형과 무관하게 앞면 → 정답을 뒤집어 보기만 하고,
채점도 기록도 하지 않는다. 그래서 두 유형이 섞여 있어도 공부하기는 똑같이 동작한다.

## 2. JSON 형식

```json
{ "type": "term", "front": "앞면", "back": "뒷면",
  "distractors": ["오답1", "오답2"], "tags": ["태그"],
  "explanation": "채점 후 펼쳐지는 설명", "starred": false }

{ "type": "mcq", "question": "질문", "choices": ["보기0", "보기1", "보기2"], "answer": 1,
  "tags": [], "explanation": "" }
```

규칙:

- `tags`·`explanation`·`starred`는 두 유형 공통이며 모두 생략할 수 있다
- `starred: true`면 핵심 단어(★)로 표시된다. 앱에서 별 버튼으로 켜고 끌 수도 있다
- `answer`는 **0부터 세는 인덱스**다. `choices`가 4개면 0~3
- `choices`는 2개 이상
- `distractors`는 단어 카드에만 있고 선택 사항이다
- `id`·`deckId`·`stats`는 **쓰지 않는다**. 앱이 붙인다

### 파일 바깥 껍데기

셋 중 아무 모양이나 된다. 두 불러오기 화면 모두 셋 다 받는다.

```json
{ "decks": [ { "deck": { "name": "덱 이름" }, "cards": [ ... ] } ] }   // 여러 덱 (내보내기가 만드는 모양)
{ "deck": { "name": "덱 이름" }, "cards": [ ... ] }                    // 덱 하나
[ ... ]                                                                // 카드만
```

`deck.name`은 **설정 → 백업 파일 가져오기**로 넣을 때 새 덱 이름이 된다. 이름이 없으면 그 덱은 건너뛴다.
반대로 **덱 화면 → 불러오기**는 이미 열려 있는 덱에 카드를 붙이므로 `deck`을 무시한다.
그래서 카드만 있는 배열로도 충분하다.

## 3. 좋은 카드의 조건

- **한 카드에 한 개념.** 답이 "A이고 또 B"가 되면 두 장으로 쪼갠다
- **뒷면은 한 문장.** 문단이 필요하면 카드를 쪼개거나 `explanation`으로 내린다
- **오답 보기는 그럴듯해야 한다.** 정답과 같은 층위, 비슷한 길이로 쓴다. 정답만 유독 길면 읽지 않고도 맞힌다
- **`explanation`에는 "왜"를 쓴다.** 답을 다시 적지 말고, 헷갈리는 이웃 개념과의 경계를 적는다.
  이 앱에 오답노트 화면이 따로 없는 이유가 이것이다 — 채점 직후 이 자리에서 끝낸다
- **단어 카드는 같은 덱에 4장 이상 모아 둔다.** 오답 보기를 다른 카드 뒷면에서 끌어오기 때문에,
  3장 이하이거나 뒷면이 서로 너무 다르면 보기가 우스워진다. 그럴 땐 `distractors`를 직접 적는다
- 정답 위치는 신경 쓰지 않아도 된다. 출제할 때 보기 순서를 매번 섞는다

## 4. LLM에게 시킬 때

아래를 그대로 붙여넣고 마지막 줄만 바꾼다.

```text
너는 암기 카드를 만든다. 아래 규칙을 지켜 JSON 배열만 출력해라. 설명도 코드펜스도 붙이지 마라.

카드는 두 유형이다.
{"type":"term","front":"용어","back":"한 문장 정의","tags":[],"explanation":"왜 그런지"}
{"type":"mcq","question":"질문","choices":["...","..."],"answer":0,"tags":[],"explanation":"왜 그런지"}

규칙:
- answer는 0부터 세는 인덱스다. choices는 4개로 맞춰라
- 오답 보기는 정답과 같은 층위·비슷한 길이로 만들어라. 정답만 길면 안 된다
- back은 한 문장으로 끝내라. 길어질 내용은 explanation으로 내려라
- explanation에는 답을 반복하지 말고, 헷갈리는 이웃 개념과의 차이를 적어라
- id, deckId, stats는 넣지 마라
- 꼭 외워야 하는 핵심 항목에만 "starred": true 를 붙여라. 나머지는 생략해라
- 한국어로 써라

주제: <여기에 주제를 적는다>. 단어 N장, 객관식 N장.
```

받은 배열은 덱 화면의 **⋯ → 불러오기 → JSON**에 붙여넣는다. 형식이 틀린 항목은
`3번째 항목: answer가 choices 범위를 벗어남`처럼 이유와 함께 걸러지고, 통과한 것만 넣을지 전부 취소할지 고를 수 있다.

## 5. 스프레드시트에서 옮길 때

**⋯ → 불러오기 → 붙여넣기** 탭은 두 열(앞면/뒷면)을 단어 카드로 바꾼다. 탭·쉼표 구분 모두 받는다.
엑셀이나 노션 표에서 두 열을 복사해 그대로 붙여넣으면 된다.

## 6. 넣고 나서

- 카드마다 **★ 핵심**과 **틀림 n**이 쌓인다. 덱 화면 필터로 그것만 모아 볼 수 있고,
  학습 순서에서 `오답노트`·`★ 핵심`을 고르면 그것만 출제된다
- 덱이 크면 **한 번에 풀 양**(10·20·50·전체)으로 잘라서 푼다. 831장짜리 덱도 20장씩 돈다
- 시험 중 **외웠어요**를 누르면 그 카드의 틀림 기록이 0이 되어 오답노트에서 빠진다
