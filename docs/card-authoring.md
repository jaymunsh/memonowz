# 카드 만드는 법

Memonowz에 직접 작성한 카드나 다른 도구에서 만든 자료를 넣는 방법이다. JSON은 파일로 불러오고, 표의 두 열은 붙여넣기로 가져온다.

## 먼저 두 가지 덱을 둘러보기

설정에서 **예시 덱 넣기 → 가져오기**를 누르면 단어장과 플래시카드 덱이 추가된다. 파일로 가져오려면 [sample-deck.json](examples/sample-deck.json)을 저장해 **설정 → 백업 또는 덱 파일 가져오기**에서 선택한다.

- **단어장:** 시험에서 보기를 고른다. 단어 카드의 오답은 직접 지정하거나 같은 덱의 다른 단어 카드 뒷면에서 가져온다. 가능한 보기는 정답을 포함해 최대 4개이며, 오답 후보가 없으면 뒤집기로 출제한다.
- **플래시카드:** `deck.flipOnly: true`. 시험에서도 답을 떠올리고 뒤집어 `몰랐음` 또는 `알았음`으로 스스로 채점한다.
- **공부하기:** 두 덱 모두 카드를 앞뒤로 살펴본다. 학습 통계나 날짜별 기록을 남기지 않는다.

덱 유형은 덱 메뉴의 **덱 편집**에서 바꿀 수 있다. 카드의 저장 형식은 `term`과 `mcq` 두 가지이며 `qa`는 지원하지 않는다. 질문과 서술형 답은 플래시카드 덱의 `term`으로 작성한다.

## 새 덱을 만드는 JSON

아래 전체 내용을 UTF-8 일반 텍스트 파일 `frontend.json`으로 저장한다. 설정에서 파일을 선택하면 덱 이름과 카드 수를 확인하는 창이 열린다. **가져오기**를 눌러야 실제로 추가된다.

```json
{
  "deck": {
    "name": "프론트엔드 기초",
    "description": "헷갈리는 개념을 짧게 복습한다",
    "flipOnly": false
  },
  "cards": [
    {
      "type": "term",
      "front": "cohesion",
      "back": "응집도",
      "distractors": ["결합도", "추상화", "캡슐화"],
      "tags": ["설계"],
      "explanation": "한 모듈 안의 요소들이 같은 목적에 모인 정도다.",
      "starred": true
    },
    {
      "type": "mcq",
      "question": "모듈 사이의 의존 정도를 뜻하는 것은?",
      "choices": ["응집도", "결합도", "상속"],
      "answer": 1,
      "tags": ["설계"],
      "explanation": "결합도는 모듈 사이, 응집도는 모듈 내부를 본다."
    }
  ]
}
```

`answer: 1`은 두 번째 보기인 `결합도`를 가리킨다. 출제 때 보기 순서가 섞여도 정답은 함께 옮겨진다.

### 각 필드의 규칙

| 유형 | 필수 필드 | 규칙 |
|---|---|---|
| `term` | `type`, `front`, `back` | 앞면과 뒷면은 비어 있지 않은 문자열 |
| `mcq` | `type`, `question`, `choices`, `answer` | 보기는 빈 문자열 없이 2개 이상. 정답은 0부터 세는 정수이며 보기 범위 안이어야 한다 |

공통 선택 필드는 `tags`(문자열 배열), `explanation`(설명 문자열), `starred`(핵심 표시 여부)다. 생략하면 태그는 빈 배열, 핵심 표시는 꺼진 상태다. `distractors`는 단어 카드에만 사용한다. 자동으로 다른 카드의 답을 쓰는 것이 어색하면 직접 지정한다.

직접 작성하는 교환 파일에 `id`, `deckId`, `stats`를 넣을 필요는 없다. 앱이 새로 만든다. 덱 이름은 `deck.name`에 적는다. `deckName`이라는 필드는 지원하지 않는다.

JSON에는 주석, 끝 쉼표, `...`를 넣을 수 없다. 따옴표는 큰따옴표를 사용한다. 텍스트 안의 줄바꿈은 `\n`, 큰따옴표는 `\"`로 적는다. `.json`이라는 확장자만 바꾼 Word 문서는 JSON 파일이 아니다.

### 뒤집기 덱 예시

```json
{
  "deck": { "name": "면접 질문", "flipOnly": true },
  "cards": [
    {
      "type": "term",
      "front": "응집도가 높은 모듈의 특징은?",
      "back": "모듈 안의 요소가 하나의 책임을 중심으로 모인다.",
      "explanation": "함께 바뀌는 요소를 같은 모듈에 두는지 살펴본다."
    }
  ]
}
```

### 기존 덱에 카드만 추가하기

덱 메뉴의 **불러오기 → JSON 파일**에서는 다음처럼 카드 배열만 담아도 된다.

```json
[
  { "type": "term", "front": "coupling", "back": "결합도" },
  { "type": "term", "front": "cohesion", "back": "응집도" }
]
```

여기서는 선택한 파일의 카드를 현재 덱에 추가한다. 파일에 `deck`이 있어도 덱 이름과 유형은 바뀌지 않는다. 여러 덱 파일을 선택하면 그 안의 카드를 현재 덱에 모아 넣는다. 통계와 이어하기를 복구하는 용도로 쓰지 않는다.

반대로 **설정**에서 카드 배열만 가져오면 덱 이름이 없어서 건너뛴다. 새 덱을 만들려면 `{ "deck": { "name": "이름" }, "cards": [...] }` 구조를 사용한다.

여러 덱을 한 번에 만들 때는 다음 구조를 쓴다.

```json
{
  "decks": [
    {
      "deck": { "name": "영단어", "flipOnly": false },
      "cards": [{ "type": "term", "front": "apple", "back": "사과" }]
    },
    {
      "deck": { "name": "용어 설명", "flipOnly": true },
      "cards": [{ "type": "term", "front": "HTTP란?", "back": "웹에서 요청과 응답을 주고받는 프로토콜" }]
    }
  ]
}
```

### 오류가 있을 때

덱 불러오기 화면은 저장 전 미리보기와 제외할 항목의 번호·이유를 보여준다. `answer`가 보기 범위를 벗어나거나 `back`이 빠진 카드는 제외한다. **정상 카드 N장만 넣기**를 누르면 통과한 카드만 저장하며 **전부 취소**로 돌아갈 수 있다.

설정에서도 일반 덱 파일의 잘못된 카드는 경고와 함께 제외한다. 파일 자체가 올바른 JSON이 아니면 읽지 못한다. 전체 백업 파일은 통계와 참조의 일관성이 필요하므로 잘못된 내용을 일부만 복원하지 않는다.

## Excel·Google Sheets에서 붙여넣기

1. 첫 열에 앞면, 둘째 열에 뒷면을 적는다.
2. 제목 행을 제외한 두 열의 내용만 복사한다.
3. 덱 메뉴 → **불러오기 → 붙여넣기**에서 카드 목록에 붙인다.
4. **카드 나누기: 한 줄에 한 장**, **앞뒤 나누기: 탭 (Excel·Sheets)**을 선택한다. 기본 설정이다.
5. 미리보기의 앞뒤와 장수를 확인하고 **N장 넣기**를 누른다.

붙여넣기는 `term` 카드를 만든다. 제목 행도 내용으로 처리하므로 자동으로 제거되지 않는다. 구분자가 없는 줄이나 앞뒤가 빈 줄은 위치와 이유를 보여주고 제외한다.

직접 입력할 때는 앞뒤 구분자를 **직접 입력 → `::`**로 바꾸고 아래처럼 쓸 수 있다.

```text
cohesion::응집도
coupling::결합도
```

긴 답을 쓸 때는 **카드 나누기: 빈 줄 사이에 한 장**, **앞뒤 나누기: 줄바꿈**을 고른다. 첫 줄이 앞면, 나머지가 뒷면이 된다.

```text
응집도란?
모듈 안의 요소가 한 목적에 모인 정도.

결합도란?
모듈 사이의 의존 정도.
```

쉼표 구분은 첫 쉼표로 앞뒤를 나누는 간단한 텍스트 처리다. 따옴표를 해석하는 CSV 파서는 아니므로 복잡한 CSV 대신 표의 두 열을 탭으로 복사한다.

## LLM으로 카드 초안 만들기

앱 자체에 AI 기능은 없다. 다른 도구에서 아래 프롬프트로 초안을 만든 뒤 내용의 정확성을 검토해 파일로 저장한다.

```text
다음 자료에서 암기할 카드 10장을 만들어라.
출력은 {"deck":{"name":"복습","flipOnly":false},"cards":[...]} 구조의 유효한 JSON만 작성해라.
설명 문장, 마크다운 코드펜스, 주석, 생략 기호를 출력에 넣지 마라.
term 카드는 type, front, back을 사용하고, mcq 카드는 type, question, choices, answer를 사용한다.
mcq의 choices는 비어 있지 않은 문자열 4개, answer는 0부터 세는 정답 인덱스다.
한 카드에 한 개념만 담고, 오답 보기는 정답과 같은 층위와 비슷한 길이로 쓴다.
설명은 explanation에, 태그는 tags 배열에 넣어라. id, deckId, stats는 쓰지 마라.
자료에 없는 사실은 추측하지 마라.

자료: 여기에 공부할 자료를 붙인다.
```

출력 전체를 `review.json`으로 저장해 설정에서 가져온다. 배열만 출력받았다면 새 덱을 만든 뒤 그 덱의 JSON 파일 불러오기를 사용한다. JSON을 텍스트 붙여넣기 칸에 넣는 방식은 지원하지 않는다.

## 가져온 뒤 공부하기

덱 화면에서 검색·유형·태그·핵심(★)·틀림 필터를 고르면 그 범위로 공부하거나 시험을 본다. 학습 설정에서 랜덤순·글자순과 10·20·50·전체 장수를 고른다. 틀린 카드만 보려면 순서가 아니라 **틀림 필터**를 사용한다.

시험 결과의 카드 상세에서 **외웠어요**를 누르면 해당 카드의 누적 틀림 횟수를 0으로 바꾸어 틀림 필터에서 빠지게 한다. 지난 날짜별 채점 기록은 유지된다.

## 교환 파일과 전체 백업은 다르다

- **덱 내보내기:** `{ deck, cards }`. 카드 내용·태그·설명·핵심 표시·덱 유형을 공유하는 용도다. 학습 통계와 기록은 담지 않는다.
- **설정 → 전체 백업 내보내기:** `version: 1`. 덱·카드·누적 통계·생성 시각·진행도·날짜별 채점 기록을 담는다. 직접 작성하기보다 앱에서 만든 파일 그대로 보관한다.
- **설정 → 백업 또는 덱 파일 가져오기:** 전체 백업의 기록과 이어하기를 함께 복원한다. 기존 덱을 유지하며 새 ID로 덱을 추가한다. 같은 파일을 두 번 가져오면 덱도 두 번 생긴다.

테마·글자 크기·마지막 학습 설정은 전체 백업에 포함되지 않는다. 자료는 접속한 주소의 브라우저에 저장된다. 로컬 주소에서 배포 주소로 옮기거나 기기·브라우저를 바꾸기 전에 전체 백업을 다운로드하고 새 주소에서 복원한다.
