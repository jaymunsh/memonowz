# 폰에서 테스트하기

Memonowz는 PWA다. **개발 서버로는 확인할 수 없는 것들**(설치, 오프라인, 아이콘, 안전영역)이 있어서
빌드된 결과물을 폰으로 열어봐야 한다. 두 가지 방법이 있고 목적이 다르다.

## 1. 같은 와이파이에서 열기 — 화면 확인용

```bash
pnpm build            # 또는 ./node_modules/.bin/tsc -b && ./node_modules/.bin/vite build
./node_modules/.bin/vite preview --host 0.0.0.0 --port 4173
```

터미널에 `Network: http://<내부IP>:4173/`가 찍힌다. 내부 IP는 이렇게도 볼 수 있다:

```bash
ipconfig getifaddr en0     # 와이파이
```

폰이 같은 와이파이면 그 주소로 바로 열린다.

**이걸로 확인되는 것**: 레이아웃, 터치 영역, 폰트, 한 줄 스크롤, 셀렉트 휠 피커, 831장 스크롤 성능.

**확인 안 되는 것**: 서비스워커는 **HTTPS 아니면 localhost**에서만 등록된다.
`http://172.30.x.x`는 안전하지 않은 출처라 오프라인 캐시가 아예 안 붙는다.
홈 화면에 추가는 되지만 껍데기만 추가되는 셈이다.

## 2. 임시 HTTPS 주소 — 설치·오프라인 확인용

`cloudflared`가 있으면 한 줄이다. 위의 preview를 띄워둔 채로:

```bash
cloudflared tunnel --url http://localhost:4173
```

`https://<랜덤이름>.trycloudflare.com` 주소가 출력된다. 로그인도 계정도 필요 없다.
이 주소로 폰에서 열면 **실제 배포와 똑같은 조건**이 된다.

**알고 쓸 것**: 임시로 인터넷에 공개되는 주소다. 주소를 아는 사람은 누구나 들어올 수 있고,
터미널을 끄면 사라진다. 데이터는 각자 브라우저의 IndexedDB에만 있으므로 남이 들어와도
내 덱은 보이지 않는다.

### 아이폰에서 확인할 것

1. 사파리로 열기 → 공유 → **홈 화면에 추가**
2. 홈 화면 아이콘이 제대로 보이는지 (전구 아이콘, 잘림 없이)
3. 그 아이콘으로 실행 → 상단에 사파리 주소창이 없어야 한다
4. **비행기 모드로 바꾸고 다시 열기** — 앱이 뜨고 덱이 그대로 있어야 한다
5. 한 번도 안 나온 한자·한글이 오프라인에서 시스템 폰트로 떨어지는지
   (폰트는 프리캐시가 아니라 런타임 캐시라, 본 적 없는 글자 범위는 오프라인에서 못 받는다)
6. **설정 → 모든 덱 내보내기가 되는지** — iOS 웹앱은 다운로드가 막히는 경우가 있다.
   백업이 유일한 안전망이라 이게 안 되면 별도 대책이 필요하다

### 왜 홈 화면에 추가가 중요한가

사파리 탭으로만 쓰면 **7일 동안 안 들어갔을 때 IndexedDB가 통째로 지워진다**(ITP).
덱도 학습 기록도 사라진다. 홈 화면에 추가한 웹앱은 이 규칙에서 빠진다.
`navigator.storage.persist()`는 사파리에서 사실상 동작하지 않으므로,
아이폰에서는 **홈 화면에 추가 + 주기적 백업**이 유일한 방어다.

## 3. 계속 쓸 거면 — 배포

trycloudflare 주소는 터미널을 끄면 사라진다. 폰에서 계속 쓰려면 고정 HTTPS 주소가 필요하다.
정적 파일(`dist/`)만 올리면 되므로 Netlify·Vercel·Cloudflare Pages 아무거나 되고 무료다.
SPA라 **모든 경로를 `index.html`로 보내는 설정**만 잊지 말 것.
