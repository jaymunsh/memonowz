# Memonowz

브라우저에 덱을 저장하고, 카드를 공부하거나 시험을 본 뒤 틀린 것만 다시 푸는 암기용 PWA입니다. 계정과 서버는 사용하지 않습니다.

## 주요 기능

- 단어장: 단어 카드와 객관식 문제를 보기 중에서 고릅니다. 직접 지정한 오답 보기가 없으면 같은 덱의 다른 단어에서 뽑습니다.
- 플래시카드: 답을 떠올린 뒤 뒤집고 스스로 채점합니다.
- 공부하기: 기록 없이 앞뒤를 넘기며 살펴봅니다.
- 시험보기: 검색·유형·태그·오답·핵심 필터를 적용하고, 순서와 장수를 선택합니다. 단어장에는 10초 제한을 설정할 수 있습니다.
- 덱별 이어하기와 마지막 시험 결과를 유지합니다. 새 시험을 시작하면 해당 덱의 마지막 결과를 교체합니다.
- 진행 중인 시험은 이어하기를 우선 표시합니다. 접힌 학습 설정에서 새 시험을 시작하거나 장수·순서·시간 제한을 바꿀 수 있으며 마지막 선택을 기억합니다.
- 카드 목록의 정답은 기본으로 숨기며, ‘정답 표시’ 선택을 기억합니다.
- 학습 기록에서 날짜별 정답률과 자주 틀린 카드를 확인합니다. 시험을 중간에 나가거나 새 시험을 시작해도 채점한 기록은 유지됩니다.
- 카드 생성·편집·삭제, JSON 파일과 텍스트 붙여넣기, 덱 내보내기, 전체 백업과 복원을 지원합니다.
- 라이트·다크·시스템 테마, 키보드 조작, 모바일 안전영역을 지원합니다.
- 설정에서 글자 크기를 기본·크게·아주 크게(16·18·20px 기준)로 조절합니다. 문제, 답, 입력창과 보조 문구도 함께 커집니다.

시험에서는 숫자키로 보기를 고르고, Space로 답을 보거나 다음 문제로 넘어갑니다. 뒤집기 채점은 답을 본 후 `1`(몰랐음)·`2`(알았음)으로 합니다. 공부하기에서는 Space로 답 보기·다음, 방향키로 이전·다음 카드를 조작합니다. 입력창과 편집 모달에서는 학습 단축키가 동작하지 않습니다. 버튼에 포커스가 있으면 Space는 해당 버튼의 기본 동작을 유지합니다.

## 실행

Node.js 24와 Corepack을 사용합니다. `packageManager`에 pnpm 버전이 고정되어 있습니다.

```sh
corepack pnpm install --frozen-lockfile
corepack pnpm dev
```

pnpm이 설치되어 있다면 `corepack pnpm` 대신 `pnpm`을 사용해도 됩니다.

```sh
corepack pnpm check        # strict TypeScript와 단위 테스트
corepack pnpm build        # 프로덕션 PWA 빌드
corepack pnpm preview      # 빌드 결과 확인
```

## 테스트

```sh
corepack pnpm test
corepack pnpm exec playwright install chromium
corepack pnpm test:e2e
```

Vitest는 스키마·파서·출제·편집 변환·저장소 트랜잭션·마이그레이션·백업을 검증합니다. Playwright는 실제 IndexedDB를 사용해 편집, 이어하기, 새로고침, 저장 실패 재시도, 백업 복원과 모달 키보드 조작을 검증합니다. 브라우저 테스트마다 새로운 브라우저 컨텍스트를 사용하므로 개인 덱에 접근하지 않습니다.

설치된 Chromium을 사용하려면 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`에 실행 파일 경로를 지정할 수 있습니다. GitHub Actions에서는 테스트, 타입 검사, 빌드와 Chromium 브라우저 테스트를 실행합니다.

## 데이터와 백업

데이터는 접속한 주소의 브라우저 IndexedDB에 저장됩니다. 다른 주소·브라우저·기기에서는 자동으로 공유되지 않습니다. 브라우저 데이터를 삭제하기 전에 전체 백업을 내보내세요.

- **덱 메뉴 → 덱 내보내기:** `{ deck, cards }` 형식의 교환용 파일입니다. 덱 유형, 카드 내용과 핵심 표시를 포함하며 학습 통계는 포함하지 않습니다.
- **설정 → 전체 백업 내보내기:** `version: 1` 형식으로 덱·카드·통계·생성 시각·세션·날짜별 채점 기록을 보존합니다. 화면 설정은 이 브라우저에 별도로 저장됩니다.
- **설정 → 가져오기:** 파일을 확인한 뒤 기존 덱을 유지하면서 새 덱으로 추가합니다. 전체 백업은 ID를 새로 매기고 세션 참조도 함께 옮깁니다. 같은 파일을 다시 가져오면 별도의 덱이 추가됩니다.
- **덱 → 불러오기:** 파일의 카드 내용만 현재 덱에 추가합니다. 학습 기록을 복구하려면 설정에서 전체 백업을 가져오세요.

이전 `{ decks: [{ deck, cards }] }` 백업과 단일 덱 파일도 읽을 수 있습니다. 이전 백업에 없던 통계·세션은 복원할 수 없습니다. 단일 카드 배열은 덱의 불러오기 화면에서 사용합니다.

날짜별 기록은 이 기능 추가 후 실제로 채점한 답부터 쌓입니다. 이전 버전에는 답마다 날짜를 저장하지 않아 과거 누적 통계를 날짜별로 나눌 수 없습니다. 카드를 삭제하거나 ‘외웠어요’를 눌러도 지난 채점 기록은 유지되며, 덱을 삭제하면 해당 덱의 기록도 삭제됩니다. 글자 크기와 마지막 학습 설정은 백업에 포함되지 않습니다.

카드 작성 형식은 [카드 작성 가이드](docs/card-authoring.md), 실제 예시는 [예시 덱](docs/examples/sample-deck.json)을 참고하세요.

## 구조

| 경로 | 역할 |
|---|---|
| `src/types` | Zod 스키마, 카드·덱·세션·백업 계약 |
| `src/db` | Dexie와 IndexedDB, CRUD·트랜잭션·백업 |
| `src/card` | 편집 폼과 카드 초안 변환 |
| `src/deck` | 홈, 덱 목록과 학습 조건 |
| `src/study` | 출제 엔진, 공부·시험·결과 |
| `src/import` | 파일 검증, 붙여넣기와 설정 |
| `src/ui` | 디자인 토큰, 공통 UI·아이콘 |
| `src/app` | 라우팅, 테마, 오류·저장소 처리, 공통 덱 생성 |
| `tests/e2e` | 브라우저 회귀 테스트 |

학습 통계, 세션 진행도와 날짜별 채점 기록은 하나의 트랜잭션으로 저장합니다. 저장 실패 시 다음 문제로 진행하지 않으며, 같은 답으로 재시도해도 횟수가 중복 누적되지 않습니다.

## 배포와 모바일 확인

`dist/`를 HTTPS 정적 호스팅에 배포하고 모든 앱 경로를 `index.html`로 보내는 SPA fallback을 설정하세요. PWA 설치와 오프라인 확인은 개발 서버가 아닌 빌드 결과로 진행합니다. 자세한 절차는 [로컬·모바일 테스트](docs/local-testing.md)에 있습니다.

화면에 필요한 폰트 서브셋은 실행 중 캐시합니다. 오프라인에서 처음 보는 글자 범위에는 시스템 폰트가 사용될 수 있습니다.

초기 설계·계획 문서는 `docs/superpowers/`에 보관되어 있으며, 현재 기능과 데이터 계약은 이 README 및 코드가 기준입니다.
